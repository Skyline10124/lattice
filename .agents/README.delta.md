# Delta 项目 Skills

本文件用于 Delta 会话。共享入口位于 `skills/<name>/SKILL.md`，工作方法与项目要求由共享入口维护，Delta 使用自己的文件、命令、检索和协作能力执行这些方法。

## 源工作流与加载

共享入口要求读取源工作流时，使用 Delta 当前可用的文件读取能力打开 `~/.agents/skills/<name>/SKILL.md`，将 `~` 展开为当前用户主目录。直接读取源文件，不再次调用同名 skill，以免递归命中项目入口。附件、模板和脚本相对于源目录解析；全局源只读。换机器时先核对源文件是否存在，缺失则报告，不自动安装或改全局配置。

在 Delta 会话中核对实际加载的项目 skill 路径和当前工具目录。调用命令、发现优先级和配置方式以当前 Delta 版本为准，不能由 Pi 的加载结果推定；本说明不假定所有版本提供相同的工具名称。

## 工具与执行

- 文件读写、补丁、内容检索和命令执行使用 Delta 实际提供的工具。先读目标、限定修改范围，编辑后检查差异；遇到权限拒绝不换工具绕过。
- GitHub 由 Delta 的命令执行能力调用 `gh-app`，遵循[Git 规范](../docs/governance/git-operations.md)。入口缺失或身份无法核实时暂停远程操作，不回退个人凭据。
- 网页研究使用 Delta 可用的搜索和页面读取能力，优先官方一手来源。库资料优先使用环境已提供的官方 Context7 接口；若不可用，说明限制并使用可访问的官方文档。不为补能力自行启用 MCP 或修改凭据配置。
- 需要独立审查时，先核对 Delta 是否提供获准的独立 Agent 能力。可用时明确输入、边界和验收，保持同一工作目录一个写者，审查不改对象，子 Agent 不自行再委派或做 Git/GitHub 写操作。没有该能力时披露单 Agent 核对；任务明确要求独立审查的部分仍待完成。
- 任务进度和会话回溯使用 Delta 自身能力；没有相应工具时在当前任务中记录进度，并请求补充不可见的历史，不在仓库另建任务账本。

源工作流中的具体工具调用按操作目的对应到上述能力，不要求 Delta 加载 Pi 扩展、角色或运行记录。实际执行了什么、失败了什么及未验证范围分别报告。

## 项目约束

先遵循根及目标路径的 `AGENTS.md`，领域资料的读取顺序见[领域文档指引](../docs/agents/domain.md)。源工作流中的 `CONTEXT.md` 操作统一由项目 domain-modeling skill 适配到 `docs/reference/glossary.md`。

中文写作、文档归属和状态遵循[文档生命周期](../docs/governance/document-lifecycle.md)。源模板中的自动提交、发布、长篇报告或任务账本要求不扩大当前授权；权限与凭据边界遵循[Agent 身份与权限](../docs/governance/agent-permissions.md)。
