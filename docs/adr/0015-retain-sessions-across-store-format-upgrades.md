# ADR 0015：会话库升级格式时保留旧会话

## 背景

### 现状

以下按 `main` 的 `5918287c` 核对。

| 方面 | 现状 | 出处 |
| --- | --- | --- |
| 旧数据 | 会话库格式不符时整库拒绝打开，由人删除或存档；理由是“本机是唯一用户，旧数据没有保留义务”，“迁移或只读保留旧数据”列为否决方案 | [ADR 0006 第 2 节](0006-tree-session-and-global-redb-store.md#2-旧数据) |
| 打开 | 打开时不初始化、不修复记录，也不迁移或替换旧版本库；不符合当前格式的库需要另行获准处理 | [身份、版本与打开](../architecture/storage.md#身份版本与打开) |
| 升级频率 | 格式版本 v8 到 v11 分别在 2026-11-10、11-11、11-18 与 11-25 递增，约每周一次 | `crates/lattice-session/src/store/codec.rs:19` 的提交历史 |
| 检查时机 | 后台启动时不打开会话库（`StoreManager` 初始为 `Unopened`），`Status` 只读内存状态；格式版本要到第一个用到库的请求打开库时才检查，不符即报 `UnsupportedVersion`。`lattice daemon restart` 在 `systemctl` 成功后只核对后台协议，不碰会话库，库格式不符时照样报成功 | `crates/lattice-server/src/stores.rs:59-62`、`crates/lattice-server/src/local/server.rs:509`、`crates/lattice-session/src/store/codec.rs:204-216`、`crates/lattice-cli/src/commands/daemon/install.rs:686` |
| 记录编码 | 每条记录是 4 字节格式版本头加规范 JSON；`blobs` 表的值是版本头加原始图片字节 | [身份、版本与打开](../architecture/storage.md#身份版本与打开) |

### 问题

IM 网关（[ADR 0011](0011-im-gateway-inside-backend.md)）把 Telegram 私聊的上下文也存进会话库。库格式一升级，后台对每条消息只能回复拒绝原因，直到有人上机器归档旧库；归档之后，对话上下文也没有了。维护者在 2026-11-26 决定从现在开始保留旧会话。按约每周一次的升级频率，转换机制要在下一次升级（v12）之前就位；nightly 预发布（#439）还会让升级更频繁。

## 决策

### 1. 保留范围

从格式版本 `11` 起，升级会话库格式时保留全部会话。更早的版本不补转换。

### 2. 每次升版登记一份转换

- 格式版本每递增一次，`lattice-session` 同时登记一份从上一版到这一版的转换，没有登记就不能递增版本号。
- 转换在规范 JSON 层进行：读入旧版本的值，产出新版本的值，不保留旧版本的 Rust 类型。`blobs` 表的图片字节原样复制，只改写版本头，除非那次升版改的就是 `blobs` 本身。
- 一次升级先确定从库中版本到当前版本的转换链，再依次应用各份转换。
- 转换表达不了的改动称为硬切，例如 v9 把项目绑定从路径哈希改为路径，哈希不可逆。硬切需要维护者在对应 PR 中明确批准，并在登记表中显式登记。转换链上有硬切时整体拒绝，不做部分转换，也不写副本，按第 5 节报告。

### 3. 原子与可回退

- 转换前先把库文件复制为同目录下带原版本号的副本，例如 `lattice.redb.v11.bak`，副本写完并同步后才开始转换；副本保留，由人删除。旧二进制读不了新格式，回退到旧二进制时用副本替换库文件。
- 升级在一个 redb 写事务中改写全部表，提交前对转换结果运行与打开时相同的整库严格校验。结果按提交是否确定分三种：

  | 情形 | 库的状态 | 报告 |
  | --- | --- | --- |
  | 提交前失败：转换出错或严格校验不通过 | 事务未提交，库保持原样 | 失败的版本与原因 |
  | 提交成功 | 已是当前格式 | 从哪一版升到哪一版，以及副本路径 |
  | 提交返回错误 | 不确定：除 `TransactionPoisoned` 外，事务可能已经持久，不能当作已回滚（[事务与一致性](../architecture/session/concurrency.md#事务与一致性)） | 按现有的保守策略停写，关闭并重新打开会话库，读出实际的格式版本并做严格校验后报告实际状态；无法确认时报“结果未知”，并给出副本路径 |

### 4. 打开仍不迁移

打开会话库的规则不变：格式不符即拒绝，打开时不转换。升级只经第 5 节的入口进行。

### 5. 由升级命令触发

升级入口面向[宿主平台](../architecture/platform.md)规定的 systemd 用户服务部署，沿用 `restart` 与 `install` 的后台管理流程。

- 后台提供两项本地 IPC 操作：只读元信息表的库格式查询（不扫描整库），以及升级。协议版本随之递增一次。
- 升级期间，后台不接受用到会话库的请求；格式查询等升级结束后再回答。两者都由 `StoreManager` 协调。
- `lattice daemon restart` 与 `lattice daemon install` 在 `systemctl` 成功并核对完后台协议之后查询库格式：

  | 库的状态 | 行为 |
  | --- | --- |
  | 不存在，或已是当前格式 | 照常成功 |
  | 有登记的转换 | 执行升级，按第 3 节报告：提交成功时照常成功；提交前失败或结果未知时以 `1` 退出 |
  | 转换链上有硬切 | 不动数据，也不写副本；报出旧会话将读不了以及归档方法，以 `1` 退出 |

- 升级请求发出后没有收到回执（例如连接中断）时，CLI 不推断结果，而是重新查询库格式：已是当前格式就按升级成功报告，仍是旧格式就按未升级报告，查询也失败时报“结果未知”。升级操作遇到已是当前格式的库时直接返回，所以查询之后重新执行是安全的。

- 绕过 CLI 重启（直接用 `systemctl`、开机自启或崩溃后自动拉起）时不升级。第一次用到库的请求仍报 `UnsupportedVersion`，诊断提示执行 `lattice daemon restart`。

### 6. 门禁

`lattice-session` 增加一项测试，按转换链逐份检查全部历史夹具：

- 格式版本常量必须等于登记表中的最高版本；每一版都保留一份旧格式夹具库，加入后不再删除。
- 每份夹具附一份按当前版本表达的预期结果：全部会话与 Turn 的身份、整棵会话树的节点与分支、当前节点、会话设置，以及图片的摘要与字节。升版时随转换一起更新各夹具的预期结果。
- 到当前版本的转换链上没有硬切的夹具：升级必须成功，通过整库严格校验，且经读接口取得的内容与预期结果一致。只通过严格校验不够：漏掉整个会话的转换也可能得到自洽的库。
- 转换链上有硬切的夹具：升级必须明确拒绝，原库文件逐字节不变，也不写副本。
- 递增版本号而没有登记转换或硬切、没有附夹具与预期结果，或任一夹具的结果不符合上述要求时，测试失败。

## 归属

| 概念 | 状态持有者 | 规则执行者 | 只使用结果的组件 |
| --- | --- | --- | --- |
| 格式版本与转换登记表 | `lattice-session` | `lattice-session` 的升级函数：唯一执行转换、校验、提交与写副本的位置 | `lattice-server` |
| 库格式查询与升级的线上类型 | `lattice-ipc` | `lattice-server`：转交 `lattice-session`，并经 `StoreManager` 在升级期间挡住用到库的请求 | `lattice-local`、`lattice-cli` |
| 提交结果不确定时的核对 | 无持久状态 | `lattice-server` 的 `StoreManager`：沿用现有的停写、关闭与重新打开，读出实际格式版本 | `lattice-cli` |
| 何时升级 | 无持久状态 | `lattice-cli` 的 `restart` 与 `install` | 用户 |

## 否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 维持硬切 | 每次升级都丢失全部会话；IM 在有人处理之前只能拒绝消息 |
| 打开时自动转换 | 后台会在没人要求时做不可逆的改动，与“打开不修复、不迁移”冲突 |
| 单独的升级命令 | 部署后台统一经 systemd 用户服务管理，更新二进制后本来就要执行 `restart`；由同一入口完成转换，避免另记一条命令 |
| 保留旧版本的 Rust 类型做转换 | 每个旧版本都要保留一套类型与编解码；规范 JSON 层的转换不需要 |
| 多格式只读兼容 | 读路径要长期同时支持多种格式，复杂度随版本累积 |
| 重启前预警库格式变化 | 旧后台不认识新格式，新二进制目前也报不出自己的库格式（#440），先做重启后的升级；预警见 #442 |

## 与其他 ADR 的关系

- 部分取代 [ADR 0006](0006-tree-session-and-global-redb-store.md) 第 2 节中“旧数据没有保留义务”，以及否决方案中的“迁移或只读保留旧数据”：对格式版本 `11` 及之后的会话库，改按本 ADR 保留与转换。第 2 节拒绝 `sessions.git` 与 `invocations.git` 旧库的规则不变。
- 与 [ADR 0013](0013-user-image-input.md) 第 2 节的 `blobs` 格式一致：转换按原样复制图片字节。
- [ADR 0011](0011-im-gateway-inside-backend.md#3-后台由-systemd-user-service-托管)第 3 节的部署范围已按本次审查中的维护者决定收窄，见[宿主平台](../architecture/platform.md)；开发调试与隔离测试保留直接启动后台的能力。

## 影响

- **代码**：`lattice-session` 增加转换登记表、升级函数、格式查询与门禁测试；`lattice-ipc` 增加两项操作并递增协议版本；`lattice-server` 转交请求，并在升级期间协调 `StoreManager`；`lattice-cli` 的 `restart`、`install` 在核对协议之后触发升级。
- **数据**：升级后会话库目录多出带原版本号的副本，由人删除。
- **合同**：修订[身份、版本与打开](../architecture/storage.md#身份版本与打开)中的打开与升级规则；[实现模块与公开操作](../architecture/session/operations.md)补 `restart`、`install` 的升级行为；场景卡片[后台与升级](../development/scenarios/manual/daemon-and-upgrade.md)同步。
- **流程**：每个递增会话库格式版本的 PR 都附转换、新增一版的旧格式夹具与预期结果，并更新已有夹具的预期结果；做不到转换时附维护者批准的硬切登记。
- **存储增长**：保留之后会话库只增不减，`blobs` 不回收；打开时整库扫描的耗时与常驻内存随之增长，见 #441。
