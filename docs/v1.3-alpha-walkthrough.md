# LATTICE v1.3-alpha Capability Boundary Walkthrough

This document explains what the v1.3-alpha release gate proves, what is deferred to beta, and how to run the non-gating Layer-2 real-LLM checklist.

See also: [`docs/CEP.md`](./CEP.md), [`scripts/release-gate-v1.3.sh`](../scripts/release-gate-v1.3.sh).

## What The Offline E2E Test Proves

The release gate (`scripts/release-gate-v1.3.sh`) runs a **deterministic, fully offline** integration test called `release_e2e_criterion_8` (`crates/lattice-api/tests/release_e2e.rs`).

This test drives a fixed tool-call sequence through the production native registry using a fake streaming LLM client. It asserts the complete pipeline:

| Step | What is verified |
|------|-----------------|
| `envelope.declare` | Intent + scope + capabilities + verify command registered; audit row created |
| `command.run` (timeout enforced) | Command policy gate runs; timeout limit respected; audit row records `impact_kind = Command` |
| `workspace.patch` (verify fails) | Patch applied; verify command exits non-zero; `VerifyFailed` recorded; diff retained as `on_failure = retain_diff` |
| `workspace.patch` (verify passes) | Narrowed scope fix applied; verify exits 0; audit row records `impact_kind = Mutation` |
| Turn committed | `SessionGraphStore` persists the turn; no legacy direct access anywhere in the path |
| Audit trail | `audit.query` returns rows for every CEP call; `audit.replay` reconstructs the PROV `wasInformedBy` chain |
| Attestation | `AttestationRecord` row created in audit DB; wire shape is forward-compatible for signed attestation (deferred) |

### CEP Warn-Mode Coverage

`scripts/cep-boundary-check.sh` verifies:
- `lattice-agent` does not depend on `lattice-cep-native` or `lattice-tooling`
- retired direct executor symbols are absent from agent-facing seams
- No legacy ToolExecutor re-export in agent-facing seams

## Manual Real-LLM Dogfood Checklist

`scripts/p27-real-dogfood.sh` is a **manual, non-gating** script that exercises the full stack with a real provider.

```sh
ANTHROPIC_API_KEY=<your-key> scripts/p27-real-dogfood.sh
# or
OPENAI_API_KEY=<your-key> P27_MODEL=gpt-4o scripts/p27-real-dogfood.sh
```

It is explicitly **not** called by `scripts/release-gate-v1.3.sh` — no API keys or network access are required to pass the gate.

Scenarios covered:
1. `envelope.declare` + `workspace.patch` — mutation path with verify
2. `envelope.declare` + `command.run` — command enforcement path

## What is deferred to v1.3-beta

The following items are explicitly out of scope for v1.3-alpha:

| Item | Reason / Reference |
|------|--------------------|
| **Signed attestation** | Key management infrastructure not yet defined |
| **Real handler re-execution in replay** | Shadow-workspace replay requires additional isolation work |
| **Real-LLM e2e as a gating CI check** | Would reintroduce model/network/key dependence; revisit post-alpha |
| **Mass docs relocation to `docs/internal/`** | Structured reorg is a separate effort |
| **Production transport attestation cards** | Runtime attestation DB is forward-compatible; signing deferred |
| **Signed invariant cards** | Card format stabilized; signing infrastructure deferred |
| **Rich prompt compilation** | Token budgets and layer priorities are a separate milestone |
| **TUI** | Will be rebuilt on top of `lattice-api` post-alpha |
| **Plugins and multi-agent orchestration** | Plugin contracts and DAG runners are future milestones |

## Running the offline gate

```sh
# From repo root — no API keys or network access required
scripts/release-gate-v1.3.sh
```

Expected output ends with:
```
================================================================
 release-gate-v1.3.sh PASSED
================================================================
```

The gate uses `set -euo pipefail` — the first failing step exits immediately. Fix issues in the order they appear.
