# Lattice Signal 设计系统

> 类型：参考资料 · 设计系统

Lattice Signal 安静、精确，带一点不祥的预感：做旧的纸面，一种 iris 墨色，设备面板式的无衬线标注配等宽的读数，还有聚成光点的光。所有东西读起来都像 1980 年代的一台仪器，正在朝某件事倒数——磁带盒上的标签、CRT 屏幕的荧光、录像带上的 VHS 条纹。

## 目录与使用

- `tokens.json`：颜色、字体、间距、圆角、线宽和抖动的唯一来源，Paper 与 Tape 两套主题。
- `tokens.css`：由 `tokens.json` 生成的 CSS 变量，网页端加载它；修改时改 `tokens.json` 再重新生成。
- `components/`：网页端参考实现。`bundle.js`（React 18，挂在 `window.LatticeSignal`）、`bundle.css` 和类型声明 `index.d.ts`；每个组件或展示卡一个目录，含说明 `README.md` 和预览 `preview.html`。预览页需要宿主页面先注入 `tokens.css`、字体、React 18 与 `bundle.js`，单独打开不会显示样式。
- `assets/Icons/`：50 个 IBM Carbon 图标原始 SVG 与 Apache-2.0 许可。
- `fonts/sarasa-ui-sc/`：网页用更纱黑体切片的 CSS 与许可；切片本身不在仓库中，获取方式见该目录的 README。
- 本文是品牌与使用规范；`components/` 下各组件的说明目前为英文，尚待中文化。TUI 实际用色以 [TUI 交互与视觉](../../architecture/tui.md) 合同为准，完整色表见 [Cassette Futurism 配色资产](../cassette-futurism-palette.md)。

## 内容原则

- 少说。一屏只放一个标题、一个数字或一个框、一句话——"AN AGENT · 2027.01.01"、"93 06 47 43"、"SOMETHING IS COMING."
- 英文的标题、标签、状态标签和标语用大写加宽字距（`title`、`label`、`tagline`）；无衬线和衬线里的文字一律句首大写。
- 并列的信息用间隔号 ` · ` 分开，不用竖线或破折号。
- 日期写作 `YYYY.MM.DD`，计数写成两位并补零（`06`，不写 `6`）。
- 状态标签是一个大写英文单词：`PROMPT`、`INFO`、`WARN`、`ERROR`、`OK`。强调标签也只写一个短词（NEW、BETA、LIVE），不写状态词。
- 陈述句以句号结尾。不用感叹号，不用 emoji，不说“我们”。
- 中文沿用同一种语气：以“。”结尾的短陈述句，如“即将到来。”。用全角标点（，。：「」）；数字、日期和产品名保持半角，与中文之间各留一个空格（“第 3 次运行”“Lattice 已就绪。”）；状态标签保持英文，与 TUI 一致。

## 视觉基础

**主题。** `Paper` 是默认主题：奶油色纸面配 iris 墨色。`Tape` 是同一套系统的夜间版——Lattice TUI 的深海军蓝终端，奶油色文字，iris 作交互色。下面每条规则在两个主题里都成立。

**颜色。** `paper` 是底色；`ink` 是正文唯一的文字色，`ink-muted` 用于标签和元信息——两者都在 `paper` 和 `field` 上核对过对比度。`signal` 是唯一的亮 iris：主按钮（文字用 `on-signal`）、链接、悬停和聚焦时字段的底线、选中和打开时的填充，以及焦点环。`haze`、`glow`、`line` 是同一 iris 的浅色，不承载文字。`control` 与 `haze` 同色，是控件的底色——除了框，系统用填色而不是框线来划出区域；`line` 只留给两种框（包括用细线框做的提示条）和表格的行线。

**状态。** 从磁带配色里取三个一冷一暖的强调色，每个只用于自己的状态，并且总是配上文字：`vhs-red` 表示错误，`amber` 表示警告，`phosphor` 表示成功和提示。在状态标签上它们是填充色，标签文字用 `on-status`；作为文字时放在 `paper` 或 `field` 上。`amber` 不扩散到警告以外的地方。错误和成功分属不同色系（红对青），并且总带文字，不单靠颜色区分。磁带配色还可以用在强调标签上（见下），但那时它们只是颜色，不表示状态。

**分类色。** 需要区分“几类东西”时——图表的系列、分段进度条的各部分——用 `series-1` 到 `series-4`：iris、琥珀、青、红，取自磁带配色，按这个顺序分配，不循环、不跳号。颜色跟着事物走，不跟着排名走：同一个东西在所有地方都用同一个颜色，筛掉别的类别时也不重新上色。它们比 VHS 本色深或浅一阶，以便在两套主题里都满足分类配色的检查（亮度带、彩度、色弱可分辨 ΔE ≥ 12、在 `paper` 上至少 3:1）。红排在最后，因为它和错误色相近：只有四类时才出现，而且从不表示状态。第五类不加新颜色，归入“其他”或拆成多张图。颜色永远不是唯一的标识，旁边总有图例或直接标注；数值和标签的文字用 `ink` 或 `ink-muted`，不用系列色。强调标签与分类色说同一件事时用同一色系（比如“记忆”在标签上是 `cyan`，在图上就是 `series-3`）。

**VHS 条纹。** 唯一借自磁带包装的装饰：三条色带，顺序固定为 `vhs-red`、`vhs-amber`、`signal`（横排自上而下，竖排自左向右），由 `Stripe` 组件绘制，有三种形态：

- **宽带**（`band`）：每条高 `space-2`、间距 `space-2`，横贯全宽。每屏最多一处——主视觉底部、框下说明的上方、章节分隔。
- **细线**（`line`）：三条 `dither-pixel` 粗的线、间距 1px，总高 `space-2`。用来给页面或打印页的上下边缘收边。
- **侧脊**（`spine`）：三根竖条（宽为 `space-2` 的一半、间距 `dither-pixel`），贴在内容左侧 `space-4` 处、与内容等高，像磁带盒侧脊上的色标。标出一个视图里的关键数字，或一组（最多四张）卡片各自的标题。

三种都不放在文字后面，不换色、不换顺序，也不用来表示状态。

**字体。** 三种字体，各司其职。西文字体和思源宋体用一个请求从 Google Fonts 加载：`family=JetBrains+Mono:wght@400;500&family=IBM+Plex+Sans:wght@400;500&family=IBM+Plex+Serif:ital,wght@0,400;0,500;1,400&family=Noto+Serif+SC:wght@400;500`。更纱黑体不在 Google Fonts 上，由本系统自带：加载 `fonts/sarasa-ui-sc/sarasa-ui-sc.css`（或把整个 `fonts/sarasa-ui-sc/` 目录复制到自己的站点）。两边的中文字体都按 Unicode 区段切成小块，页面只下载实际显示的字。

- `sans`（IBM Plex Sans）是主力，所有给人读的字都用它。`title` 在框上方用一次，`tagline` 在框下方用一次，`heading` 做页面分节标题，`label` 用于单位和字段标签——这四种用大写加宽字距，像设备面板上的标注；`ui-heading` 用于面板和对话框标题，`text` 用于段落、说明、按钮文字和提示信息，`text-small` 用于次要界面文字——这三种句首大写。
- `mono`（JetBrains Mono）只用在字符必须对齐、或本身就是机器文字的地方：`numeral` 用于倒计时、统计和时间这类会跳动或要对齐的数字；`code` 用于代码、命令、路径、ID、哈希和日志行，可以单独成行，也可以嵌在 `text` 里；`meta` 用于版本号、构建号、时间戳、字节数这类机器元信息。此外只有状态标签里的单词和名称字标用等宽。一句给人读的话，哪怕紧跟在状态标签后面，也用 `text`。
- `serif`（IBM Plex Serif）是人的嗓音，刻意少用：每页一句 `display` 宣言，长页面开头一段 `lede`，一段斜体 `quote`。不用于控件、表格或标签。

每个页面都以无衬线为底：产品界面基本只用无衬线，公告和长文再加衬线；等宽只在上面列出的场合出现，一屏里等宽的文字应明显少于无衬线。所有字体最粗只到 500——强调靠字号、字距和换字体，不靠加粗。衬线斜体是唯一的斜体。

**中文。** 每种字体都给汉字接了一个中文备用字体，拉丁字母和数字仍用原来的西文字体：`sans` → 更纱黑体（Sarasa Gothic SC），`serif` → 思源宋体（Noto Serif SC），`mono` → 更纱黑体（与终端的习惯一致）。本机装了更纱黑体时直接用本机字体，否则下载自带的网页版（更纱黑体 UI SC，汉字字形与更纱黑体相同）。所以中英混排不需要额外标记；页面设置 `lang="zh-CN"` 即可。中文文字要调整三处：

- 中文没有大写，宽字距也没有直接对应：短标签（`label`、`title`、`tagline`，每个词四个字以内）保持原字距；用这些样式排成句的中文，字距收到 `0.08em`。
- 段落保持原行高（`text` 24px，`lede` 32px）；中文 `display` 大标题行高约 1.3 倍（44px 字号配 56px 行高）。
- 没有斜体：中文 `quote` 用直立字体加「」，并设置 `font-synthesis: none`，避免浏览器把汉字拉斜。

自带的网页版更纱黑体只有常规体（400）：写作 500 的地方，汉字显示为常规体，拉丁字母仍是 500；不要靠字重区分中文层级。等宽行里的一个汉字比两个西文字符还宽；中英混排时不要按字符数对齐列。

**框。** 系统的容器，分两种，都是直角、`paper` 填充：

- **定位框**（默认）：四条 `line` 色的边，线宽 `stroke-frame`，在四个角断开；每个断口正中是一个 `ink` 色十字，线宽相同，臂长 `mark-arm`；十字臂末端与边之间再留一个 `mark-arm`，让十字独立出来。内边距 `space-12`。每页最多一个，只给页面最核心的那一件事用，上方配 `title`、下方配 `tagline`。
- **细线框**（`plain`）：一圈连续的 `line` 色细线，线宽 `stroke-hairline`（1px），没有十字，内边距 `space-6`。用于其他需要边界的地方——设置面板、代码块、列表里的卡片，可以重复出现、并排摆放。

定位框里不嵌套任何框；两种框都不加阴影和圆角。

**标签。** 系统里用来强调的小色块，分两种，形制相同：

- **状态标签**：实色矩形：`signal`（PROMPT）、`amber`（WARN）、`vhs-red`（ERROR）或 `phosphor`（OK），文字用等宽大写（字号和字距同 `label`，与 TUI 一致）、`on-status` 色（`signal` 上用 `on-signal`），左右内边距 `space-2`，直角 `radius-none`——就是 TUI 的模式标签，搬到了纸面上。词固定，只用于状态。
- **强调标签**：同样的形制，换成磁带配色——`iris`（`signal`）、`red`（`vhs-red`）、`amber`（`vhs-amber`，文字用 `on-vhs-amber` 深蓝，像磁带盒上的琥珀色贴纸）、`cyan`（`phosphor`）和 `ink`（`ink` 底、`paper` 字）。用于不是状态的词：NEW、BETA、LIVE、分类、版本号，可以放在标题旁、列表和表格行首、卡片角上。同一个意思始终用同一种颜色；一组里最多三四种颜色；强调标签不写状态词（WARN、ERROR、OK），表示状态时用状态标签。

**控件。** 按钮、输入框、多行输入框、下拉选择、开关、复选框、单选框和分段控件共用一套规则：

- 直角；按钮、输入框、下拉选择和分段控件高 40px，多行输入框从 40px 起按行数增高（`space-6` + `space-4`），左右内边距 `space-4`；文字用 `text`。
- 用底色而不是框线：所有控件——按钮、输入框、多行输入框、下拉选择、分段控件、开关、复选框和单选框——都填 `control`，不画边框；悬停时填 `glow`（字段例外，见下）。字段（输入框、多行输入框、下拉选择）底部保留一条 1px（`stroke-hairline`）的 `ink-muted` 底线，表明这里可以输入——在 `control` 上 Paper 主题 5.2:1、Tape 主题 4.9:1，满足至少 3:1 的要求；悬停和聚焦时底线换成 `signal`。
- 开关是一条 36 × 18px 的 `control` 底色轨道（与复选框同高，不超过一行文字），里面一根 `ink-muted` 的竖条滑块，与轨道等高、宽为轨道的四分之一，贴着左端；打开时轨道填 `signal`，滑块换成 `ink` 并贴到右端（用 `on-signal` 的话，滑块会和轨道外的底色连成一片，开关看起来像短了一截）。选中的复选框填 `signal`，里面是 `on-signal` 对勾；选中的单选框保持 `control` 底色，中间是一个 `space-2` 见方的 `signal` 小方块。
- 所有控件都是方的，单选框也不例外；单选框和复选框靠选中后的样子区分——一个是中间的小方块，一个是整格填色加对勾。
- 主按钮是 `signal` 实色，每个视图最多一个，悬停时变为 `ink` 实色；其余操作用次按钮，`control` 底色、`ink` 文字，悬停时变为 `glow`。按钮文字动词开头、句首大写，如 “Run agent”；最多带一个 20px 的前置图标，只有图标的按钮必须提供读屏文字。
- 字段标签用 `label` 样式放在框上方；提示用 `text-small` 放在框下方；出错时底线加粗到 `stroke-focus` 并和说明一起换成 `vhs-red`，说明要写成一句告诉用户怎么改的话。路径、ID、命令这类机器值用 `mono` 输入框。输入框、多行输入框和下拉选择共用这一套字段结构；下拉选择右侧是方头折线箭头，展开时翻转向上；浏览器支持时（`appearance: base-select`），展开的列表与字段等宽、没有边框，`paper` 色的选项排在一圈 `control` 底色里，文字与字段对齐，悬停的一项填 `glow`，已选的一项填 `signal`；不支持的浏览器保留系统原生列表。
- 禁用时整体降到 50% 不透明度，不换颜色；需要解释的限制写在旁边，不要只靠禁用。
- 立即生效的设置用开关，随表单提交的选择用复选框，二到五个互斥选项用单选框；在页面内切换视图或模式（列表 / 网格、24h / 7d / 30d）、立即生效的二到五个互斥选项用分段控件——一条 `control` 底色的长条，段与段之间不加分隔线，悬停的一段填 `glow`，选中的一段填 `signal`、文字用 `on-signal`；六个及以上的选项用下拉选择。一行放不下的回答用多行输入框。

**提示条、进度与表格。**

- 提示条：一行消息，前面是状态标签（`INFO` 用 `signal`，其余沿用 `OK`、`WARN`、`ERROR`），后面一句 `text`，右侧最多一个次按钮；外框就是细线框（`plain`），内边距收紧到 `space-4`。不加彩色侧边条、图标或阴影，状态由标签表达。放在事情发生的地方，不浮在页面上；错误提示会被读屏立即播报。
- 进度条：一排等宽方格，亮起的是 `signal`，未亮的是 `haze`，格间距 `dither-pixel`；值由几部分组成时（比如上下文窗口里的系统、工具、对话、缓存）用分段模式：每部分按 `series-1` 到 `series-4` 各点亮自己的一段格子，最多四段，下方一行图例用 `text-small` 写出名称和数值，像多声道的电平表；上方左侧是 `label`，右侧用等宽数字写百分比。格子整格点亮，不做缓动或流光——像磁带机的电平表。步数少时格数等于步数（12 次工具调用就是 12 格）。长度未知的任务不用进度条。
- 表格：表头用 `label` 样式，下方一条 `ink-muted` 细线；行与行之间是 `line` 细线，行高 40px；不做斑马纹、竖线或外框。ID、次数、时长、大小用等宽字体，数字列右对齐、ID 左对齐；状态列放状态标签。

**抖动。** 抖动是这套系统画“光”和“图”的唯一方式，用得不多：主要做背景，偶尔做特别的图片。

- 画法：有序抖动（Bayer 4×4）。每个像素是 `dither-pixel`（2px）见方的方块，全部落在同一张全页像素网格上，按 1:1 绘制；色调只靠像素疏密和色阶表达，不用模糊、透明度或渐变，不用圆形裁剪，像素不做圆角。
- 色阶：由浅到深依次是 `haze`、`glow`、`signal`、`ink`（Tape 主题里越往后越亮）。用多级有序抖动：一个色调落在两级之间时，按 Bayer 阈值在这两级之间抖动，所以相邻色阶自然过渡，边缘被打散而不是一条线。
- 背景：只用浅端两级 `haze` 和 `glow`，像素稀疏；光点排在规则网格上，四角大、中间小，放在纯 `field` 上、内容后面。文字下方没有 `paper` 时，不要让光点穿过文字。
- 图片：主视觉、空状态插图这类特别的图片，才用满全部四级，最深到 `ink`。一页最多一张。色调指的是离底色的距离：Paper 里越深越远，Tape 里越亮越远；画有光照的图时按主题换算，Paper 里阴影取高色调，Tape 里亮面取高色调，否则 Tape 里会像底片一样明暗颠倒。
- 点缀色：特别的图片可以多一个磁带色点缀层——`vhs-amber`、`vhs-red` 或 `phosphor` 中的一个，比如落日、信号灯、指示灯。点缀只占画面一小块（五分之一以内），按自己的密度单独抖动，画在 iris 色阶之上；一张图只用一种点缀色，背景永远不用。
- 做法见“抖动”展示卡里的脚本：每个像素按位置算出 0 到 1 的色调，再换算成色阶。

**间距与布局。** 居中、对称的构图。`space-2` 连接数字和它的单位，`space-6` 隔开框和它上下的文字，`space-12` 是框的内边距和倒计时格之间的间距。手机上保留 `space-6` 的页边距，倒计时改为两行两列。

**两种密度。** 同一套颜色、字体、形状和用色规则，分两档尺寸：

- **展示档**（默认）：落地页、首屏、空状态、发布公告。40px 控件，`space-2` 到 `space-12` 的间距，宽字距的大写标题和标签，以及定位框、VHS 条纹、抖动和衬线大字这些招牌元素，都只在这一档出现。
- **紧凑档**：应用界面——会话列表、工具调用日志、设置、检查器、工具栏。在容器上加 `ls-compact`，里面的组件自动收紧：控件和表格行高 `control-compact`（28px），文字 `compact-text`（13px），间距加入 `space-1`（4px）和 `space-3`（12px），字段标签和表头用 `compact-label`（11px，字距 0.08em），机器值用 `compact-code`（12px 等宽），标签 11px、字距 0.12em，开关 32 × 16，复选框和单选框 16px。
- 紧凑档里一律句首大写，只有 `compact-label` 用大写；0.24em 以上的宽字距只留给 16px 以上的展示档文字。窗格之间用 `line` 细线分隔，不用定位框；选中行填 `glow`，悬停填 `control`；密集列表里焦点环画在行内侧，不压到相邻的行。

**形状、层次与动效。** 全部直角（`radius-none`），系统里没有圆形元素——连光点也是方形像素抖出来的；Carbon 图标里的圆形笔画是唯一的例外。没有阴影，也没有渐变。动效克制：数字原地变化，不滑动；光点可以缓慢呼吸（周期 4 秒以上），在用户开启“减少动态效果”时停止。不加扫描线、闪烁或假的磁带噪点。

**焦点与选中。** 键盘焦点是 `signal` 色实线环，线宽 `stroke-focus`，外侧留 2px `paper` 色间隙（Paper 主题在 `paper` 上 4.9:1，Tape 主题 5.2:1）。悬停时填色控件变为 `glow`、字段底线变 `signal`；表格选中行填 `glow`，文字保持 `ink`。

## 图标

界面图标统一用 IBM Carbon Icons（Apache-2.0，许可证见 `assets/Icons/LICENSE.txt`），它和 IBM Plex 同属一套设计语言。通过 `Icon` 组件使用：

- 尺寸只用 16、20、24、32px 四档：16 配 `text-small` 和表格，20 配正文、按钮和控件，24、32 只用于空状态和大标题旁。
- 颜色跟随文字（`currentColor`）：通常是 `ink` 或 `ink-muted`，在主按钮里自动变成 `on-signal`。不给图标单独配色，也不用状态色给图标上色——状态由状态标签表达。
- 图标辅助文字，不替代文字：按钮最多带一个前置图标；只有图标的按钮必须提供读屏文字。
- 系统收录了 50 个常用图标，原件在 “Icons” 素材组；需要更多时从 `@carbon/icons` 的 32px 原稿里取，原样使用，不重画、不改线宽，也不混用其他图标库。

没有标志：名称用 `mono` 字体、`ink` 色排出。除图标外，定位框上的十字、抖动像素和 VHS 条纹是仅有的图形元素，用 SVG 按各自的 token 绘制。

## 组件

`Tag`、`Frame`、`Countdown`、`Button`、`Input`、`Switch`、`Checkbox`、`Radio`、`Segmented`、`Textarea`、`Select`、`Notice`、`Progress`、`Table`、`Icon` 和 `Stripe` 位于 `components/bundle.js`，挂在 `window.LatticeSignal` 上，需要页面上有 React 18，并加载 `tokens.css`、`components/bundle.css`，以及加载上述字体（见“字体”）。它们的类名都以 `ls-` 开头。同一页面上有多个 React 根时，给每个根设置不同的 `identifierPrefix`，让输入框自动生成的 id 不重复。

## 在 GPUI 中使用

这套系统同时用于网页和 GPUI 原生界面。上面的“视觉基础”是两边共同的规范；`components/` 里的 React 组件和 CSS 是网页端的参考实现，GPUI 端按同样的规范另写，看到的效果应当一致。下面列出 GPUI 端需要另外处理的地方。

- **密度**：GPUI 主界面默认用紧凑档，展示档只用于欢迎页、空状态这类大场面。
- **Token**：`tokens.json` 是唯一来源。GPUI 端从它生成 Rust 主题（Paper、Tape 各一套颜色，加上间距、线宽、字号），不手抄数值。主题跟随系统的亮色和暗色外观，在 Paper 和 Tape 之间切换，也允许用户手动指定。
- **字距**：GPUI 的文字样式没有字距属性，而 `title`、`label`、`tagline` 和标签的宽字距是这套视觉的核心，不能省略。用一个专门的文字元素逐字排版，在字与字之间加上相应的间距（`em` 换算成当前字号）。只有这几种短文字需要它，正文照常排版。
- **字体**：网页端按 Unicode 区段切好的字体包只能在网页上用。GPUI 端随应用打包完整字体：JetBrains Mono、IBM Plex Sans 和 IBM Plex Serif、更纱黑体 UI（常规体）、思源宋体，均为 OFL 许可。中英混排用字体回退链：西文字体在前，汉字回退到更纱黑体或思源宋体，顺序和网页端的字体栈相同。
- **焦点环**：GPUI 没有带外间距的描边。在控件外面多套一层，画出 2px 的 `paper` 间隙加 `stroke-focus` 粗的 `signal` 环，尺寸和网页端相同。只在键盘操作时显示。
- **悬停与选中**：用 GPUI 自带的悬停、按下和聚焦样式，颜色规则不变：填色控件悬停时变为 `glow`，字段底线变为 `signal`，选中的一项填 `signal`。
- **控件**：网页端的输入框、多行输入框、下拉选择、复选框、单选框和开关都建立在浏览器原生控件上，GPUI 端需要自己实现，或者给现成的组件库换上这套主题。下拉选择展开后按规范来画：与字段等宽，没有边框，`paper` 色的选项排在 `control` 底色上，文字与字段对齐，悬停的一项填 `glow`，已选的一项填 `signal`。
- **抖动**：在画布上逐像素计算，色阶和阈值与“抖动”展示卡里的脚本相同。绘制时把同一行里相邻、同色的像素合并成一个矩形再画，减少绘制数量。动画约每秒 12 帧，一次呼吸至少 4 秒。GPUI 读不到系统的“减少动态效果”设置，做成应用内的开关，关闭时光点静止。
- **像素对齐**：`dither-pixel`、线宽和十字角标都按设备像素取整，不让一个像素落在两个设备像素之间。高分屏上 2 个逻辑像素可能对应 3 或 4 个设备像素，这没有问题；需要避免的是落在半个像素上。
- **图标**：Carbon 图标是单色 SVG，作为资源打包，颜色取当前文字色。尺寸同样只用 16、20、24、32。
- **响应式**：网页端用容器查询的地方（倒计时在窄于 640px 时变成两行两列），GPUI 端按元素拿到的实际宽度判断，阈值不变。
