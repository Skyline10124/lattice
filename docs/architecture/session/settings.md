# 会话的 profile 副本

> 所属领域：[会话与 Turn](README.md)

会话持有一份 profile 副本，此后只用副本，不再读取原 `agent.toml`。这样已有会话的行为不随 profile 文件的修改而变化，重新打开会话时也能确定接下来用什么配置。

- **内容。** 有效 profile（外部策略文件解析所得的工作区、网络和观察限制填回具体字段）；系统提示，按内容摘要引用配置表；当前的 provider `id`、模型 `id` 与推理档位。副本不含 provider 配置、模型元数据与凭据，它们由请求网关每次请求时取得，见[模型接入合同](../llm/README.md#组成与归属)。
- **创建。** 新会话首次被接受时，后台读取提交所指定 agent 的 profile，核对所选的 provider 与模型可用，在接受事务中写入副本。
- **使用。** 之后的提交只用副本。
- **修改。** 提交带有模型或推理档位的选择时，选择在这一轮的接受事务中写回副本。提交指定了 agent 时，用该 agent 的 profile 重新生成副本，提交没有选择模型或档位时取该 profile 的值。
- **选择随提交生效。** 选择没有随提交发出就不保留。所以副本中的模型与档位总是最后一次被接受的提交所用的值，重新打开会话时沿用它们。
- **`rewind` 不改变副本。** 副本属于会话，不属于节点。每一轮实际使用的 agent、模型、provider 与档位仍记在它的 UserMessage 节点上。
- **原 profile 的修改只对新会话生效。** 包括收紧的 LANCET 策略（写权限、网络白名单）；要让已有会话使用新的 profile，开新会话或提交时重新指定 agent。provider 配置、元数据与凭据不在副本中；其中用于请求发送的数据修改从下一次请求起对所有会话生效，价格的生效时机见[费用估算](../llm/usage.md#费用估算)。
- **新会话必须指定 agent。** 副本在会话第一次被接受时写入，此后每个会话都有副本。

一轮的模型与推理档位按以下顺序取得：

- **模型。** 提交选择的模型，其次是副本中的模型，再次是 profile 的 `[agent].model`。都没有时在接受前按配置错误拒绝。
- **推理档位。** 准入时经 `GatewayTurn::prepare` 按档位策略选择档位：
  - **严格策略（`EffortPolicy::Strict`）**：提交显式选择了档位（`--effort` 或 TUI `/effort`），或未显式选档位且本次模型未变（沿用会话副本中的当前档位，新会话或重新指定 `--agent` 时取 `agent.toml` 的 `[agent].effort`；为空表示不发送档位参数）。所求档位不为模型支持时在接受前按配置错误拒绝，诊断末尾标明档位来源：显式选择为 `(from --effort)`，`agent.toml` 为 `(from [agent].effort in <路径>)`，会话副本为 `(from session profile copy)`。
  - **回退策略（`EffortPolicy::Fallback`）**：本次更换了模型且未显式选择档位时，依次尝试基础档位（已有会话副本的当前档位，新会话或重新指定 `--agent` 时为 `[agent].effort`）与 `[agent].effort`，选用新模型支持的第一个；两者都不支持时不发送档位参数。可用档位及与档位选择无关的推理文字请求规则见[模型接入合同](../llm/reasoning.md#推理档位)。
