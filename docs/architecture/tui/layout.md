# 布局

> 所属领域：[TUI 交互与视觉](README.md)

## 水平与垂直分配

尺寸以终端字符单元为单位。右侧栏宽度固定为 40 列，列间空隙 `gap = 1`。左列不留边距，正文、标题线与输入区都从左列第一列开始。

| 条件或尺寸 | 规则 |
| --- | --- |
| 侧栏可见 | `frame_w >= frame_h × 3` 且 `frame_w - 40 - 1 >= 72` |
| 侧栏可见时 | `left_w = frame_w - 40 - gap`，`content_w = left_w` |
| 侧栏隐藏时 | `left_w = frame_w`，`content_w = frame_w` |
| statusline | 左列最后一行，侧栏可见与否都存在 |
| Dock | 高度由栈顶模块决定，最多 `max(frame_h - 1 - 对话记录行数, (frame_h - 1) / 2)` 行，其中除法向下取整、减法饱和 |
| 对话记录可用高度 | `frame_h - 1 - dock_h`；内容不足时只占内容行数 |

所有尺寸减法使用饱和运算，极小终端不得下溢或 panic。渲染以实际分配高度为准，不假定对话记录至少有一行。
`Dock::height()` 统一提供 Dock 高度；渲染、viewport 行数、输入折行和光标定位使用同一 `content_w`。正文宽度不另设上限。

`176 × 50` 显示侧栏，左列与正文宽均为 135；`115 × 47`、`85 × 47`、`56 × 47` 不满足比例条件，`80 × 24` 分栏后正文不足 72 列，均隐藏侧栏。

左列由上至下为对话记录、[Dock](dock.md#dock-与输入区) 与 [statusline](#statusline)。对话记录与 Dock 共享 statusline 之上的高度：Dock 紧贴对话记录最后一个可见行之下，内容不足可用高度时 Dock 随内容上移，其下到 statusline 之间留空；内容填满后 Dock 停在 statusline 之上。statusline 始终在左列最后一行。停在底部时输入区看起来就是对话的最后一段；向上翻看时，Dock 与 statusline 留在原位。侧栏全高，gap 保持空列。界面不画边框。

## 侧栏

侧栏保留显示条件、宽度与 navy-11 底色，不显示内容；身份、phase、翻页与键位提示由 statusline 显示。

## statusline

statusline 是独立组件，不属于 Dock。它占左列最后一行，使用 navy-11 底色；左侧显示 session、agent、模型、提供商与推理档位，右侧显示提示、本轮用量、上下文用量与 phase。

| 字段 | 来源 | 尚未取得时 |
| --- | --- | --- |
| session | 启动时即存在的当前 SessionId 前 8 个字符 | 始终存在 |
| agent | 会话头中的 `agent` | 始终存在 |
| 模型、提供商、推理档位 | 会话头中的 `model`、`provider`（显示 provider `id`）与 `effort`（显示档位名） | 对应字段为空时隐藏 |
| 本轮用量 | 当前路径上最近一轮各尝试用量之和：输入与输出 token、缓存命中（`cache_read` 占 `input` 的比例）与费用，例如 `↑12.3k ↓1.2k 缓存 80% $0.04`；金额格式见[费用估算](../llm/usage.md#费用估算)。token 不足 1000 时显示整数 | 未知的 token 与缓存不显示；费用见下文的本轮计量显示条件 |
| 上下文用量 | 当前路径上最近一次带用量的尝试中 `input` 与 `output` 之和，显示为 `上下文 12.3k`，不足 1000 时显示整数 | 不显示 |
| phase | `idle`、`stream`、`cancel`；观察连接中断时附加 ` · offline` | 始终存在 |
| 翻看提示 | 不跟随时显示 `↓ N 行`，N 为视图下方的对话记录行数 | 跟随时不显示 |
| 退出提示 | 第一次 Ctrl+C 后两秒内显示 `Ctrl+C to quit` | 过期不显示 |
| 换行键提示 | 焦点在输入区或编辑器时显示 `S-Enter 换行` 或 `Alt+Enter 换行`，按启动时的键盘增强探测结果选择 | 其他焦点不显示 |

本轮用量是整轮所有模型请求的累加值，不代表上下文大小，所以上下文字段只取最近一次尝试。用量口径与费用估算见[模型接入合同](../llm/usage.md#用量缓存与费用)；费用取自条目中各尝试保存的金额与确切标记（`cost.exact`），按[费用估算](../llm/usage.md#费用估算)的规则相加，只有估算金额带 `≈` 前缀。重新打开会话后，模型、提供商与档位随会话头出现，用量随初始条目出现。statusline 只使用会话头与条目中已有的字段，不为显示新增后台接口。

本轮以当前路径上最近 UserMessage 的 TurnId 为范围，累计该轮所有 Step 的尝试，包含失败与重试。每个 NodeId 的条目替换后重新派生，只取条目中一份尝试记录。新轮接受后切换本轮身份；会话头已到、当前位置的条目尚未到齐时隐藏计量，避免把旧轮或初始条目的小计当作完整值。路径替换后从新路径重建，读取更早的轮不改变本轮。

输入、输出分别按[尝试计量与完整性](../session/steps.md#关闭-step-与-turn)判断，只显示小计已知且未溢出的项；整体为 partial 时数值是已报告部分之和。有请求且明确报告的 0 显示为 `↑0`、`↓0`。token 达到 1000 后显示一位小数的 `k`。缓存命中率只在同一整轮范围内的 input、cache_read 的 `complete` 都为 true、input 大于 0 时显示，不受整体 `kind` 影响，用合计相除并四舍五入为整数百分比；保留 provider 报告可产生的超过 100% 的比例。已取得本轮计量时，费用按[费用估算](../llm/usage.md#费用估算)显示；全未知时也保留费用字段，汇总溢出时隐藏。已确认本轮没有尝试时不显示 token 与缓存，只显示费用 `$0.00`；空根、尚未接受及初始条目尚未到齐时不显示本轮费用。

上下文另取当前路径上最近一次非空的规范化用量，求 input、output 中已知项的和；两项均未知或加法溢出时隐藏，不回退到较早报告。本轮计量中的输入、输出、缓存与费用合成一个字段，整体参与空间省略。

空间不足时先省略换行键提示，再省略退出提示；仍不足时，其余字段按显示宽度从宽到窄依次省略，等宽时按上下文用量、本轮用量、推理档位、提供商、模型、session、agent、翻看提示、phase 的先后。只剩一个字段时不再省略，按显示宽度裁剪。退出提示过期须触发重绘，不能因界面空闲而残留。
