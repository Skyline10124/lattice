# Dock 与输入区

> 所属领域：[TUI 交互与视觉](README.md)

## Dock 组件

Dock 是承载模块的公共组件，位于对话记录与 statusline 之间。外壳负责模块栈、区域分配、高度夹紧与按键路由；模块负责标题线内容、所需行数、绘制、光标位置与按键解释。模块通过返回意图请求 app 执行提交、排队、记下选择、释放消息或关闭面板，不直接调用 LocalTurn。

输入区是常驻栈底模块，其上可以有一个[面板](#面板)和一条 [Warn 或 Error 消息](#warn-与-error-模块)，Dock 只显示栈顶模块。能出现的栈只有四种：

| 栈（自底向上） | 如何出现 | 如何离开 |
| --- | --- | --- |
| 输入区 | 默认 | — |
| 输入区、面板 | 在输入区执行 `/help`、`/model` 或 `/effort` | Esc 关闭面板；选择面板另可按 Enter 选定后关闭 |
| 输入区、消息 | Warn 或 Error 消息到来 | Space 释放消息 |
| 输入区、面板、消息 | 面板显示时 Warn 或 Error 消息到来 | Space 释放消息后露出面板，再按 Esc |

栈顶是面板或消息时输入区不可达，所以不会在消息之上再打开面板，也不会重复打开面板。

- 状态消息推入时由 Dock 按等级决定是否暂驻：Warn 与 Error 暂驻，Info 直接进入对话记录。Dock 自己记录暂驻的是哪一条消息以及面板是否打开，消息本身不带显示位置。
- 模块高度为上方空行、标题线与内容行之和，内容行至少 1 行，模块本身不设上限。总高按[布局](layout.md#水平与垂直分配)中的 Dock 上限夹紧：对话记录短时 Dock 可占满其下到 statusline 之间的全部空间，对话记录长时最多占一半。输入区与选择面板的候选项超出部分在模块内部滚动，帮助面板、Warn 与 Error 超出部分截断。
- 按键先经 app 处理保留键：PageUp、PageDown、Ctrl+End、Ctrl+C 与 Ctrl+D。其余按键交给焦点所在组件；焦点在 Dock 时交给栈顶模块。

## 输入区

输入区以 `── USER ──` 标题线开头，右端平时为空，有以下状态时依次写出：

| 状态 | 右端内容 |
| --- | --- |
| 当前 Turn 运行中 | `Enter 排队` |
| 排队已达上限 | `排队已满` |
| 输入超过可见行数 | `↑ n 行 · ↓ n 行`，只写有隐藏内容的一侧 |
| 有评论草稿 | `n 条评论待发送` |

- 输入区不显示提示符；每个视觉行都从正文起点开始。输入按字符折行，光标定位使用同一折行结果。
- 可见行数由 [Dock 组件](#dock-组件)的高度上限决定，不另设行数上限。超出时在输入区内部滚动，保持光标可见。
- 焦点在输入区时，终端光标定位在输入位置。输入为空时只显示光标，不显示占位文字。

## Warn 与 Error 模块

新到的 Warn 与 Error 级[状态消息](README.md#状态消息与等级)暂驻在 Dock：WARN 显示结果不确定或有内容丢失的提示，例如重试；ERROR 显示错误，包括本进程看着结束的 Turn 的失败结局；Info 与随初始条目或历史查询装入的旧结局直接进入对话记录。标题线为 `── WARN ──` 或 `── ERROR ──`，右端写 `Space 关闭`。标题的颜色取[配色](palette.md#配色与终端约定)表中的前景角色：WARN 用 Warn，ERROR 用 ToolErr。ToolErr 是界面通用的错误红色，名字来自它最初的用途，不限于工具。内容行数由 [Dock 组件](#dock-组件)的高度上限决定，不另设行数上限；超出部分截断，不增加只读滚动或展开。

Warn 与 Error 只占据 Dock，不改变焦点。新 Warn 或 Error 到来时，将旧状态释放回对话记录，新状态占据 Dock。无修饰 Space 在输入区或浏览光标下释放当前状态，焦点不变，按键被消费；对话记录中的评论或排队编辑器照常输入，包括 Space 与可打印字符，退出编辑后再用 Space 释放。状态不定时消失；暂驻 Dock 时不在对话记录重复显示，释放后在原位置出现一次：状态消息回到它出现时的位置，重试提示与结局回到所属条目中。

焦点在 Dock 时，Warn 与 Error 模块只处理 Space，其余按键一律忽略，包括普通输入、编辑、粘贴、提交与 ↑；不修改不可见的输入缓冲，也不进入浏览光标。保留键继续按条件执行。焦点在对话记录时，按键仍由对话记录处理，见[浏览光标](interaction.md#浏览光标)。

## 面板

面板显示一条 slash 命令的结果，有帮助面板与选择面板两种。面板不是状态消息，内容不进入对话记录；关闭后直接消失，再次执行命令重新打开。面板显示期间到来的 Warn 或 Error 压在面板之上，释放后面板重新显示。面板在栈顶时不修改不可见的输入缓冲，也不进入浏览光标；保留键继续按条件执行。

### 帮助面板

在输入区执行 `/help` 或 `/?` 后，Dock 显示帮助面板：标题线为 `── HELP ──`，标题与内容使用 Assistant，右端写 `Esc 关闭`。内容行数由 [Dock 组件](#dock-组件)的高度上限决定，超出部分截断，不增加滚动。帮助面板只处理 Esc，其余按键一律忽略。

### 选择面板

`/model` 与 `/effort` 打开选择面板，为下一次提交选择模型与推理档位。

- **候选项。**
  - `/model` 打开时以 `List { provider: None, ready_only: true }` 向后台查询[模型候选](../llm/models.md#模型候选)，只列出可用性为 `ready` 的候选项，写作 `<provider>/<model>`；查询返回前显示 `加载中`，失败时关闭面板并显示一条 Warn，没有 `ready` 候选时显示 `没有可选模型`。
  - `/effort` 打开时以 `Target` 查询下一次提交将使用的模型：该模型的可用性为 `invalid` 时，面板显示后台给出的具体原因，Enter 不选定档位；可用性为 `ready` 或 `unconfigured` 时，从低到高列出该模型支持的档位（未配置的 provider 保留本地可推导的档位），没有可选档位时面板只显示一行说明：`该模型不能选择推理强度，可以在 providers.toml 中补充它的推理参数写法或档位`。还不知道下一次提交将使用哪个模型时（新会话首次提交之前且没有选过模型），说明 `先用 /model 选择模型`。
- **排序。** 模型按 provider 在内置表中的顺序，其后是 `providers.toml` 新增的 provider；同一 provider 内按模型 id 排序。下一次提交将使用的值标为当前项，打开时光标在它上面。
- **过滤。** 标题线下一行是过滤文字。可打印字符与粘贴追加到过滤文字，Backspace 删除；候选项按不区分大小写的子串匹配过滤，光标移到第一个匹配项。
- **键位。** ↑↓ 移动光标，Enter 选定并关闭面板，Esc 取消并关闭面板。候选项超出可见行数时在面板内部滚动，保持光标可见；超宽的候选项按显示宽度截断。
- **标题线。** `── MODEL ──` 或 `── EFFORT ──`，标题使用 Assistant，右端写 `Enter 选定 · Esc 取消`。
- **作用范围。** 选择由 TUI 进程持有，随下一次提交交给后台，在接受事务中写回会话的 profile 副本，不写回原 profile；没有提交就退出时不保留。排队的消息发送时带上发送那一刻的选择。
- **换模型时的档位。** 选了新模型而没有另选档位时，下一次提交的档位按[会话合同](../session/settings.md#会话的-profile-副本)的规则确定：原档位新模型不支持时改用 profile 的默认档位，它也不支持时不发送档位参数。与档位选择无关的推理文字请求规则见[模型接入合同](../llm/reasoning.md#推理档位)。TUI 依据候选项中的档位与会话头中 profile 的默认档位按同一规则显示，并以一条 Info 状态消息说明档位的变化；新会话首次提交之前没有会话头，不知道默认档位，这时不显示档位，由后台在接受时确定。

已知缺口：用 `--agent` 打开已有会话时，第一次提交被接受之前，statusline 与 `/effort` 仍按旧 profile 副本显示档位。前端在首次接受之前无法查询 profile，这个缺口由 #377 跟踪。
