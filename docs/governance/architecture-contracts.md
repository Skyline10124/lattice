# 架构合同写作

> 类型：治理合同
> 上位依据：[文档生命周期](document-lifecycle.md)

## 目的与范围

本文件补充架构合同的内容组织、语义表达和审查要求，适用于 `docs/architecture/` 中的合同及既有文档中待迁入的架构约束。
语言、命名、文档状态、批准与迁移遵循上位规范。

架构合同应让读者从目标理解模型，再沿组件协作与流程推导出设计。内容组织遵循上位规范的[说明顺序与表达](document-lifecycle.md#说明顺序与表达)，本文件细化设计中需要讲清的内容。

## 边界与组织

- 按领域职责和需要共同维持的性质划分合同，使紧密关联的结构与行为能在同一上下文中理解。
- 说明适用对象、负责的职责、维护归属及与相邻领域的交界。跨领域概念引用其主定义；范围排除与必要禁止事项集中到明确小节。
- 共享规则明确唯一维护出处，其他合同引用它并说明本领域如何遵循。局部接口或操作的保证标明适用层级与范围。
- 正文按“目标与使用场景—概念与关系—职责与接口—正常流程—场景分支—保证与限制”展开。在保持概念依赖和流程完整的前提下，按领域需要合并或省略不适用的小节。

## 需要表达的设计

### 目标与使用场景

- 用简短、直接的说明交代谁要完成什么工作，系统提供什么能力，最终得到什么结果。
- 选取能贯穿设计的正常使用场景，作为后续模型、接口和流程的共同线索。读者应能从该场景理解各部分存在的理由。

### 领域模型与关键结构

- 逐个解释重要概念代表什么、承载哪些信息、参与什么操作；随后说明概念之间的关系。技术名称与具体用途一起引入，必要时给出简短实例。
- 对实体和有状态对象，明确身份、生命周期、所有权和允许的修改者。新增状态应对应流程中的实际节点，并说明谁使它发生变化。
- 明确权威事实的来源，以及视图、缓存、索引和证据各自的用途。依赖派生数据作决定时，说明它如何从权威事实得到、何时更新，以及失效或无法核验时由谁处理。
- 表达关键数据结构与关系约束，区分必须保持的设计与帮助理解当前实现的示意。

### 职责划分与接口

- 说明参与协作的组件分别负责什么，谁拥有状态、作出决定和执行效果。每项工作有明确归属，跨组件协作通过职责清晰的接口衔接。
- 接口说明输入输出的含义、调用条件和可观察效果。涉及状态、资源或跨组件协调时，说明所有权转移、持有期限及协作责任。
- 组件自行维护职责内部的顺序、状态和收尾，调用方按接口发起操作并使用结果。调用方需要反复探测、补偿或同步内部状态时，先核对职责划分能否将这些工作收回所属组件。
- 参数、结果、错误和事件引用其 schema 或协议定义，并在合同中解释必要语义。区分必须保持的接口约定、可调整的实现细节及生成产物与来源的关系。

### 数据流、控制流与生命周期

先完整叙述正常路径，再从其中的具体节点展开分支。对每条流程，说明：

| 内容 | 需要讲清的设计 |
| --- | --- |
| 起点 | 谁发起操作，要完成什么，带入哪些数据及前提 |
| 每一步 | 哪个组件接收什么，完成什么验证、判断或动作，产生哪些状态或数据 |
| 交接 | 数据交给谁，由谁推进下一步，相关资源由谁持有和释放 |
| 完成 | 哪些事实已经成立，结果如何保存，调用方或用户如何取得结果 |

- 数据流说明来源、必要的验证与转换、流向及持有者；控制流说明由谁触发、判断、调度或终止操作。图文分别标明数据传递、调用和授权关系。
- 明确必要的先后关系、允许的并发及协调方式。有状态协议说明合法迁移及触发条件；生成、发布、持久化和完成节点分别交代动作与确认条件。
- 中断、取消、重启或恢复等分支从正常流程的具体状态展开：说明触发事件、已生效的变化、仍保存的事实、后续责任方，以及用户会看到什么和可以做什么。
- 恢复和重试说明责任方依据哪些事实继续、安全前提、执行步骤、重复请求与已发生效果的识别和处理方式，以及何时完成或停止。

### 行为保证与运行限制

- 每条保证和限制对应明确的需求场景、协议可达状态，或安全与数据完整性要求，并说明采用该处理方式的理由。排除事项交代适用范围；必要禁止事项在独立小节列出对象、条件、依据和可采用的处理方式。
- 正确性、安全、并发、一致性、持久性及资源要求落实到具体对象、接口或操作，说明适用条件、观察范围与责任。跨阶段、组件或领域时限定本层保证，并引用相关定义。
- 性能目标、大小上限和重试预算说明所解决的问题、数值依据、度量对象、单位、适用范围、触发后的行为及核验方式。尚待测量或裁决的数值保留相应状态；临时测量结果归入验证记录。

#### 前提、不变量与非保证

- 调用前提说明开始操作前必须满足什么、由谁提供和核验，以及不满足时的响应。
- 不变量说明在何种范围和状态下持续成立；成功保证说明完成相应操作意味着哪些事实成立。仅在终态成立的关系明确标为终态保证。
- 环境假设说明保证依赖的条件及其核验方式；非保证集中说明本设计的能力范围与适用理由。验证结果按实际事实记录，前提和承诺的修订遵循批准流程。
- 前提拒绝、不变量破坏、环境不满足和结果未知分别落实到本领域的处理责任与可观察结果。

#### 原子性、一致性与持久性

- “原子”说明不可分割的对象或变化集合、观察者与成立条件。单个路径、多个对象、一个存储库和多个存储库分别界定其原子范围。
- 分别定义原子可见性、多对象事务、并发隔离、一致性与持久性。“一致”落实为具体事实之间必须维持的关系，各项性质分别说明保证与依据。
- 持久性说明确认成立的节点、覆盖的故障范围及依赖条件；分别交代成功返回、进程重启后读取和掉电后恢复所依据的机制。
- 例如，单文件安装说明新内容何时完整可见；涉及多文件、历史记录或外部写入者时，继续说明它们之间的协调方式与保证范围。

#### 成功、失败与恢复

- 成功和失败绑定具体操作层级与阶段。上层完成说明依赖哪些下层结果；每阶段说明实际执行的动作与产生的变化。
- 按流程可达的情形展开拒绝执行、执行中失败、部分效果已发生和结果无法确认。超时或取消后的效果以实际事实核验，错误分类由所属领域定义。
- 对影响调用方或后续状态的关键失败，说明触发条件、已生效的变化、仍成立的事实、可观察结果，以及后续由谁处理。
- 文字整理保留保证成立的条件和范围。例如，冲突检查拒绝与执行途中 I/O 失败分别说明状态；文件安装成功、后续历史记录失败时，分别保留两步的事实及后续处理方式。

## 术语、图示与资料的关系

### 术语表与合同

- 术语表提供领域概念的简短解释、关键区别、易混淆称呼和合同入口；合同维护精确语义与完整约束。
- 多个合同复用同一领域概念时，明确主定义出处；其他合同说明本领域的责任与关系，不另立相互冲突的定义。不同概念需要共用名称时，应写明领域或使用限定名称。
- 主定义尚未完成迁移时，按上位规范保留明确的旧入口。
- 概念含义或关键区别改变时，同步核对术语表与相关合同。

### 图示与示例

- 按实际需要使用 Mermaid 结构图、数据流图、时序图或状态图。图示注明节点、连线和边界的含义，区分实体、组件、状态和部署单元。
- 区分规范性的关系与仅供理解的示意。图中的顺序、并发、状态和接口应与正文一致，省略内容不能暗示不存在的保证。
- 同一关系不在多份图表中独立维护。必要的不同视图应能对应到同一约定；图由其他来源生成时，明确维护源，不手工修改产物形成平行设计。
- 示例说明适用范围内的语义及简化之处，关键边界由正文明确。

### 实现说明与决策记录

- 区分规范要求、已核验的实现事实和待裁决的设计建议。已有约束不证明相关能力已实现，当前代码行为也不能自动成为规范。
- 实现结构、生成机制或运维命令有助于理解合同时可以引用，但应与必须保持的设计约定分开。操作细节放在相应开发或参考资料中，不复制成第二套维护内容。
- 合同保留理解当前设计所需的关键理由；完整决策过程、旧方案与历史证据由 ADR 等既有记录承载。
- 文档与事实存在冲突时，依[项目宪章](charter.md#权威传递)交由有权人类裁决，不通过选择性抄写旧文档或迎合当前代码消除冲突。

## 验证与演化

架构合同应给出关键承诺的核验方式或验证入口，使审查者能核对职责、接口、数据关系、状态迁移及必要边界。
当前执行结果和未验证范围按上位规范保留在对应任务记录中。

修订时，按实际影响检查：

- 读者能否从文档解释目标、概念与职责，并沿正常流程说明每一步由谁完成、产生什么、如何进入下一步；技术名称是否已有足够的定义或示例。
- 每个新增概念、状态、确认步骤和补偿分支承担什么必要职责，依据哪个需求场景、可达路径或安全与数据完整性要求。优先用职责收敛和接口简化消除额外协调；删除无依据的假设分支，将必要性尚未确定的设计列为待裁决。
- 主流程是否完整，必要禁止事项是否集中且有依据；原有职责和保证在修订后是否得到明确承接。
- 模型、结构、接口、图示与正常及异常流转是否一致，保证是否被错误地跨阶段或跨领域传递。
- 关键条款是否能辨认适用对象、条件、效果与责任，示意或环境假设是否被误读为承诺。
- 接口或数据关系变化对调用方、已有数据和恢复路径有什么影响；明确的兼容或演化承诺如何保持或获授权修订，不为假设中的兼容预建机制。
- 术语、领域合同和既有资料是否保持唯一规则出处，未承接的有效约束是否仍有明确入口。
- 路径或锚点变化影响哪些实际读者和写入流程。文档被 skills 或工作流消费时，分别核对读取与回写入口；链接存在或旧文件改成导航，不等于消费流程兼容。

迁移的批准、替代关系和规则承接依[文档生命周期](document-lifecycle.md#迁移与唯一有效入口)执行。
