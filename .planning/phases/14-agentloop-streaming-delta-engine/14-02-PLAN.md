**Scenario 1 (VER-08, AGENT-03):** `streaming_multi_chunk_tokens_assemble_into_one_message`
- Events: [Token("p"), Token("ong"), Done { finish_reason: "stop", usage: None }]

**Scenario 2 (VER-08, AGENT-04):** `streaming_reasoning_separate_from_visible`
- Events: [Reasoning("think"), Token("answer"), Done { finish_reason: "stop", usage: None }]
- Assert: assistant_output == "answer", messages[0].content == "answer", messages[0].reasoning_content == Some("think")

**Scenario 3 (AGENT-06):** `streaming_tool_call_assembly_and_sequential_execution`
- Events: [ToolCallStart { id: "c1", name: "read_file" }, ToolCallDelta { id: "c1", arguments_delta: r#"{"path":"#}, ToolCallDelta { id: "c1", arguments_delta: r#""a.txt"}"# }, ToolCallEnd { id: "c1" }, Done { finish_reason: "tool_calls", usage: None }]
- Second round events: [Token("done"), Done { finish_reason: "stop", usage: None }]
- Tool executor returns Ok("file content")
- Assert: status == Completed, tool_results.len() == 1, tool_results[0].ok == true
- Assert event ordering: index(ModelFinished { finish_reason: "tool_calls" }) < index(ToolCallStarted { id: "c1" }) < index(ToolCallFinished { id: "c1" })
- This proves ToolCallStarted fires only after stream assembly + validation (not during LlmEvent::ToolCallStart processing)

**Scenario 4 (AGENT-05):** `streaming_incomplete_tool_call_error_no_execution`

- Assert: status == Error, assistant_output == "partial", tool_results is empty
- Assert messages[0].content == "partial", messages[0].tool_calls == None
- Assert events do NOT contain ModelFinished

**Scenario 5 (AGENT-05, D-09):** `streaming_invalid_tool_call_json_no_execution`

- Assert: status == Error, terminal_reason contains "invalid/incomplete tool call"
- Assert: tool_results is empty, events do NOT contain ToolCallStarted, events do NOT contain ModelFinished

**Scenario 6 (AGENT-06):** `streaming_multiple_tool_calls_all_valid_sequential`
