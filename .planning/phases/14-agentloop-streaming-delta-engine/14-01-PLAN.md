2. In `crates/lattice-agent/src/agent_loop/mod.rs`, add `use futures::StreamExt;` to imports.

3. Replace the `self.config.llm.chat(chat_request).await` call site (line 208) and the entire post-response processing block (lines 208-297) with a streaming implementation per D-03:
   - Call `self.config.llm.stream_chat(chat_request).await` — on Err, return Error status with "LLM error: {err}" (same as current behavior).
   - On Ok, consume the stream via a private helper method `consume_model_stream`.

4. Implement private method `consume_model_stream(&self, stream: LlmStream, events: &mut Vec<AgentTurnEvent>) -> StreamResult` that:
   - Defines a `PendingToolCall { id: String, name: String, arguments: String, ended: bool }` struct.
     `ended` records whether `ToolCallEnd` was received for this call. It is read during diagnostics
     (terminal_reason can report "closed by: tool_call_end vs done") but is NOT required for
     execution eligibility — Done + valid JSON is sufficient (some providers skip ToolCallEnd).
   - Defines `StreamResult { assistant_content: String, reasoning_content: String, tool_calls: Vec<PendingToolCall>, usage: Option<TurnUsage>, finish_reason: Option<String>, outcome: StreamOutcome }`.
   - Defines `StreamOutcome { Done, Error(String), Exhausted }`.
   - Iterates `while let Some(event) = stream.next().await` matching on LlmEvent variants:
     - Token { content } -> append to assistant_content, push AgentTurnEvent::TokenDelta { content } (per D-06)
     - Reasoning { content } -> append to reasoning_content, push AgentTurnEvent::ReasoningDelta { content } (per D-06)
     - ToolCallStart { id, name } -> if pending_calls already contains a call with the same id, return StreamOutcome::Error("invalid/incomplete tool call: duplicate id={id}"). Otherwise push new PendingToolCall (per D-08).
     - ToolCallDelta { id, arguments_delta } -> find by id in pending_calls. If NOT found, return StreamOutcome::Error("invalid/incomplete tool call: delta without start (id={id})"). Otherwise append to arguments (per D-08).
     - ToolCallEnd { id } -> find by id in pending_calls. If NOT found, return StreamOutcome::Error("invalid/incomplete tool call: end without start (id={id})"). Otherwise set ended = true (per D-08).
     - Done { finish_reason, usage } -> convert usage via `as u64` cast, return StreamResult with StreamOutcome::Done
     - Error { message } -> return StreamResult with StreamOutcome::Error(message) (per D-11)
     - Started | Citation | Signature | GroundingChunk | SafetyRating -> no-op (per D-04, D-05)
   - After loop exhausts (no Done received): return StreamResult with StreamOutcome::Exhausted (per D-12)
   - NOTE: This applies to AgentLoop's streaming consumer only. FakeStreamingLlmClient::chat() may still default missing Done to "stop" for StubLlm/chat parity (Phase 13 contract). These are two different layers.

5. After `consume_model_stream` returns, in `run_turn_inner`:
   - Accumulate usage from StreamResult.usage into accumulated_usage.
   - Match on outcome:
     - StreamOutcome::Error(msg) or StreamOutcome::Exhausted:
       - Build partial GraphMessage if assistant_content or reasoning_content is non-empty (per D-11, D-12, D-13): content = assistant_content, reasoning_content = if empty None else Some(...), tool_calls = None.
       - Push partial message to messages/all_messages if present.
       - Return AgentTurnResult with status Error, terminal_reason = "LLM error: {msg}" or "LLM stream ended without completion", assistant_output = assistant_content. Do NOT emit ModelFinished.
     - StreamOutcome::Done:
       - If tool_calls is non-empty, validate all-or-nothing (per D-09):
         - Normalize empty arguments to "{}". Write the normalized value back into PendingToolCall.arguments.
         - Validate each via `serde_json::from_str::<serde_json::Value>(&call.arguments)`.
         - If ANY invalid: do NOT emit ModelFinished, build GraphMessage with content+reasoning only (no tool_calls), push to messages, return Error status with terminal_reason "invalid/incomplete tool call: {name} (id={id})".
         - If ALL valid: emit ModelFinished { finish_reason, usage }, build GraphMessage with content+reasoning+tool_calls as Vec<GraphToolCall> using the normalized arguments, push to messages, proceed to tool execution.
       - If no tool_calls: emit ModelFinished, build GraphMessage with content+reasoning, push to messages, return Completed with assistant_output = assistant_content.

6. Tool execution loop remains structurally identical to current code (per D-10): iterate validated tool calls, emit ToolCallStarted before each execution, execute via tool_executor using the same normalized arguments string (GraphToolCall.arguments == lattice_llm::ToolCall.function.arguments — no divergence between transcript and execution input), emit ToolCallFinished after, build tool GraphMessage, push to messages. Failed tool results produce tool messages with error content — the loop continues to next round (per AGENT-07, D-10).

7. Ensure ModelStarted is still emitted BEFORE the stream_chat call (line 203-206 stays unchanged).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM stream -> AgentLoop | Untrusted stream events from provider (tool call arguments, content) |
| Tool call arguments -> ToolExecutor | JSON arguments validated before execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | Tool call argument injection | mitigate | All-or-nothing JSON validation via serde_json before any tool execution (D-09) |
| T-14-02 | Denial of Service | Infinite single stream / resource exhaustion | accept | MAX_TURN_ROUNDS caps round count but does NOT cap a single in-flight stream that never terminates. Caller timeout (optional) is the only current mitigation. Live cancellation/deadline semantics are Phase 15/17 scope. Accepted for Phase 14. |
| T-14-03 | Information Disclosure | Partial content on error | accept | Partial content committed to session graph by design; not leaked externally |
| T-14-SC | Tampering | serde_json dependency | accept | serde_json is a 9+ year old crate with 200M+ downloads, already in workspace |
</threat_model>
