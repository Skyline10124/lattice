<decision_coverage>
## Decision Coverage

- D-01: Profile remains a stable user-facing single-agent configuration file, not a runtime assembly script.
- D-03: `agent.toml` defines one generic agent profile and supports neighboring files such as `prompt.md`.
- D-04: `prompt.system_path` resolves relative to the containing `agent.toml` package directory, not process cwd.
- D-09: The v1 schema is strict allowlist only and rejects unknown sections or fields.
- D-10: Allowed top-level keys are exactly `schema_version`, `[agent]`, `[prompt]`, `[tools]`, `[security]`, `[context]`, and `[behavior]`.
- D-11: `[agent]` carries `name`, `model`, and optional `description`, and rejects `preset`, `type = "code_agent"`, `skippable`, and `tags`.
- D-12: `[prompt]` accepts exactly one of inline `system` or package-local `system_path`.
- D-13: `[security]` only carries `sandbox_mode = "project" | "strict" | "permissive"`.
- D-14: `[context]` carries simple toggles and rejects `cwd` and `project_root`.
- D-15: `[behavior]` carries generic turn controls and rejects old orchestrator behavior fields.
- D-16: This work creates a narrow `lattice-profile` crate instead of using runtime, agent, or orchestrator as a dumping ground.
- D-17: `lattice-profile` owns strict schema types, loading, package path checks, clear errors, and profile lowering foundations.
- D-18: `lattice-profile` has no runtime, orchestrator, agent, session, plugin, CLI, or TUI dependency and constructs no live agent.
- D-19: Runtime keeps environment-dependent validation for model, tool, sandbox, and handle construction.
- D-20: `lattice-agent` remains generic and knows nothing about profile files.
- D-21: Old profile fields fail fast; no compatibility, warning-ignore, dry-run migration, or automatic migration path is added.
- D-22: Legacy profile sections and fields are explicit rejection fixtures.
- D-23: Profile errors include path, section, field, value when known, rejection reason, and expected schema guidance.
- D-24: Tests cover strict rejection for unknown and forbidden sections/fields.
- D-28: Profile tool exposure uses `[tools]`, not `[capabilities]`.
- D-29: `[tools]` supports both `bundles` and `enabled` arrays.
- D-32: `lattice-profile` validates only string-array shape for `bundles` and `enabled`; runtime/tools validate actual existence.
</decision_coverage>
