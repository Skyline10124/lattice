<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime -> session | Runtime supplies profile snapshot draft, current source fingerprint, base commit id, messages, and manifest drafts. |
| profile file -> durable session | File-backed profile data becomes locked durable execution configuration. |
| concurrent caller -> session store | Multiple callers can attempt to commit against the same session head. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `open_turn` profile binding | mitigate | Store immutable `ProfileSnapshot` per session and return locked snapshot plus `ProfileDrift` instead of replacing it when source fingerprint changes. |
| T-02-02 | Tampering | `commit_turn` base validation | mitigate | Validate `base_commit_id` against current session commit before appending messages or manifests. |
| T-02-04 | Information disclosure | `ProfileSnapshotSummary` and manifest metadata | mitigate | Persist only safe profile summary and canonical profile/spec JSON; add `profile_snapshot_summary_excludes_credentials`, `profile_snapshot_source_audit_excludes_secret_fields`, and `commit_turn_manifest_metadata_excludes_secret_fields` tests to prove credential maps, API keys, raw env values, and secrets are excluded. |
| T-02-05 | Repudiation | Error/cancel turn outcomes | mitigate | Represent `completed`, `error`, and `cancelled` in `TurnOutcomeStatus` and manifest metadata when the turn has a visible/model-visible boundary. |
</threat_model>
