    Tests to write (each is a #[tokio::test]):

    1. `stream_turn_live_basic_completed` — Happy path: configure FakeStreamingLlmClient to emit token events and stop. Collect all TurnEvents. Assert:
       - First event is TurnStarted with non-empty session_id
       - Contains TokenDelta events
       - Contains ModelFinished
       - No TurnFailed or TurnCancelled
       - Contains TurnCommitting followed by TurnCommitted with status Completed
       - TurnCommitted.session_id matches TurnStarted.session_id
       - TurnCommitted.commit_id is non-empty

    2. `stream_turn_live_error_commits_error` — Configure FakeStreamingLlmClient to emit an error event. Collect events. Assert:
       - Contains TurnFailed with non-empty reason
       - TurnFailed appears before TurnCommitting
       - Contains TurnCommitted with status Error
       - No CommitFailed event

    3. `stream_turn_live_event_ordering` — Configure a multi-event sequence (ModelStarted, TokenDelta, ModelFinished). Assert ordering:
       - TurnStarted is first
       - ModelStarted appears after TurnStarted
       - TokenDelta appears after ModelStarted
       - ModelFinished appears after TokenDelta
       - TurnCommitting appears after ModelFinished
       - TurnCommitted is last

    4. `stream_turn_live_startup_failure_no_stream` — Pass a request with session_id pointing to a non-existent session. Assert stream_turn_live returns Err (not Ok with error events inside the stream). This proves API-04/API-05.

    5. `stream_turn_live_commit_stores_delta_only` — After a successful turn, read the committed turn from the session store. Note: stream_turn_live moves the SessionApi into the spawned task, so re-open a fresh SessionApi from the same tempdir path after collecting events. Assert:
       - Committed messages contain exactly: 1 user message + agent response messages
       - User message content matches request.input
       - No prior transcript messages are duplicated in the commit (COMM-01)
       - Commit message is <= 72 chars (COMM-04)

    6. `stream_turn_live_branch_populated` — Create a session, run a turn. Assert TurnStarted.branch is Some (the default branch name) when session is on a branch.

    7. `stream_turn_live_commit_failure_emits_commit_failed` — Trigger a commit failure by exercising the live path with a session whose underlying store is closed/corrupted after prepare_live_turn succeeds but before commit_turn runs. Practical approach: use a `#[cfg(test)] pub(super)` test helper in live.rs that exposes `run_live_turn_task` directly, passing a SessionApi whose SQLite file has been deleted between prepare and commit. Assert:
       - Stream contains TurnCommitting
       - Stream contains CommitFailed with non-empty reason
       - Stream does NOT contain TurnCommitted
       - HEAD is unchanged (session.status still shows the original parent_commit_id)

    Note on Cancelled path: Phase 16 does not introduce a public cancellation handle on stream_turn. The cancelled terminal event mapping is implemented in derive_terminal_event (Plan 01) and tested at the agent layer (Phase 15). Public live path Cancelled testing belongs in Phase 17 when VER-12 lands the receiver-drop and consistency tests.
