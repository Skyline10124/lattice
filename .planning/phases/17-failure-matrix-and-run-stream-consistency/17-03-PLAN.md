**NormalizedTurnObservation struct** (per D-08, D-09):
```
#[derive(Debug, PartialEq)]
struct NormalizedTurnObservation {
    status: RunTurnStatus,
    usage: Option<TurnUsageSummary>,
    assistant_output: String,
    tool_results: Vec<ToolResultSummary>,
    transcript_roles_and_content: Vec<(String, String)>,
    terminal_reason: Option<String>,
}
```

**Observation builders** (per D-09 — explicit sources):

Each consistency scenario uses a fresh one-turn session. After commit, `head_transcript` on the `SqliteSessionGraphStore` returns the committed delta (since there is only one turn, transcript.messages IS the full committed delta).

- `observe_run_turn(result: &RunTurnResult, store: &SqliteSessionGraphStore, session_id: &str) -> NormalizedTurnObservation`:
  - `status` from `result.status`
  - `usage` from `result.usage`
  - `assistant_output` from `store.head_transcript(session_id)` — find last assistant message content
  - `tool_results` from `result.tool_results`
  - `transcript_roles_and_content` from `store.head_transcript(session_id)` messages — (role, content) pairs
  - `terminal_reason` from session log entry's `terminal_reason` field (use `store.log(session_id)` for status/usage/terminal_reason metadata)

- `observe_stream_turn(events: &[TurnEvent], store: &SqliteSessionGraphStore, session_id: &str) -> NormalizedTurnObservation`:
  - Find `TurnCommitted { session_id, status, .. }` in events
  - `status` from TurnCommitted.status
  - `usage` from TurnCommitted or committed metadata
  - `assistant_output` from `store.head_transcript(session_id)` — same as run side
  - `tool_results` from committed transcript tool messages
  - `transcript_roles_and_content` from `store.head_transcript(session_id)` — same as run side
  - `terminal_reason` from TurnFailed.reason if present, else None

**Key rule (D-09):** Both sides read `assistant_output` and `transcript_roles_and_content` from the committed session store via `SqliteSessionGraphStore` (public trait), NOT from live events or result fields. Session log (`store.log`) is used only for status, usage, and terminal_reason metadata. This ensures the comparison anchors on durable history.

**LLM fake strategy:** Both `run_turn` and `stream_turn` paths call `stream_chat()` internally (the agent loop's `run_turn_inner` always uses streaming). Therefore both sides MUST use `FakeStreamingLlmClient` with the same scripted event sequence. Do NOT use a chat-only `FakeLlm` for the run side — it cannot express "error after partial tokens" and would not be equivalent.

```
let script = vec![Token{...}, Token{...}, Done{...}];
// run side:
let llm_run = FakeStreamingLlmClient::builder().events(script.clone()).build();
// stream side:
let llm_stream = FakeStreamingLlmClient::builder().events(script.clone()).build();
```

**Important (D-07):** Each scenario uses TWO independent tempdirs — one for `run_turn`, one for `stream_turn`. Never share a session store between the two paths.

**Test: `consistency_completed_content_only`** (D-11 scenario 1):
- Script: LLM yields Token("Hello, "), Token("world!"), Done{finish_reason:"stop", usage: Some({10, 5, 15})}.
- Run both paths with same input "hi", same `FakeStreamingLlmClient` script.
- `assert_eq!(observe_run_turn(...), observe_stream_turn(...))`.

**Test: `consistency_error_after_partial_token`** (D-11 scenario 2):
- Script: LLM yields Token("partial "), Token("resp"), then LlmEvent::Error{message:"provider error"}.
- Run both paths with same input "hello", same `FakeStreamingLlmClient` script.
- Both should commit with Error status, partial assistant content "partial resp" in transcript.
- `assert_eq!(observe_run_turn(...), observe_stream_turn(...))`.

**Test: `consistency_tool_call_path`** (D-11 scenario 3):
- Script: LLM first round yields ToolCallStart + ToolCallDelta + ToolCallEnd + Done (tool_calls finish_reason). Second round yields Token("result") + Done (stop).
- Both paths use identical `LoadedAgentProfile` with `read_file` tool enabled and same workspace directory containing a test file. Use `DefaultToolExecutor` — deterministic output because the file content is controlled.
- Both paths must produce identical tool_results and final transcript.
- `assert_eq!(observe_run_turn(...), observe_stream_turn(...))`.

**Test: `stream_turn_emits_activity_before_commit`** (VER-13 live ordering):
- Use the completed content-only scenario.
- Collect stream_turn events.
- Assert: at least one `TokenDelta` event appears BEFORE `TurnCommitting` in the event sequence.
- Assert: `ModelStarted` appears BEFORE any `TokenDelta`.
- Assert: `TurnCommitting` appears BEFORE `TurnCommitted`.

Register the test file in `crates/lattice-api/Cargo.toml` under `[[test]]` if needed (check if integration tests auto-discover or need explicit registration). Add `lattice-session` as a dev-dependency if not already present.
