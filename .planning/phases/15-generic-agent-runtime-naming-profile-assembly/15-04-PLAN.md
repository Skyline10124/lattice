<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI coding_agent.rs AgentSpec construction → Runtime::build_agent | CLI builds an AgentSpec with model, project_root, cwd, security, task_state_seed, and AgentPreset::Coding — all user-controlled or session-derived values cross into runtime assembly |
| CLI eval harness scripted servers → Agent.run() | Deterministic eval tests use loopback TCP servers returning controlled responses; agent tool execution runs in temp directories |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-09 | Elevation of Privilege | CLI `build_coding_agent` always uses `AgentPreset::Coding` | accept | This is the intended design: `lattice code` is the coding preset entrypoint. The coding preset is explicitly opted into via `.preset(AgentPreset::Coding)` which is a typed enum, not a string. Non-coding CLI commands (run, resolve, debug) do not use this path. |
| T-15-10 | Tampering | Task state seed from previous session manifest | mitigate | `load_latest_manifest_metadata` reads the latest turn manifest from the session store and deserializes it into `TaskState`. The seed is only applied when a previous session exists. If deserialization fails, `None` is returned gracefully. No unvalidated task state is injected. |
| T-15-11 | Information Disclosure | Eval test model names contain `"scripted-coding-*"` | accept | These are internal test identifiers, not user-facing. They are only used within `register_scripted_model` calls in test code. No production data is affected. |
| T-15-12 | Denial of Service | Eval harness loopback server binding | accept | The harness binds `127.0.0.1:0`, handles `PermissionDenied` gracefully by skipping tests, and only runs in the test environment. No production impact. |
</threat_model>
