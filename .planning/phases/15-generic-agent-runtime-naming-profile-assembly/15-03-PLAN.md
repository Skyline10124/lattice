### D-07 Structural Narrowing: Deferral Rationale

Per checker review: D-07 requires `lattice-orchestrator::assembly::assemble_agent` to narrow from a competing construction path into a profile-to-AgentSpec conversion/delegation layer. This plan does **not** implement that structural narrowing. Rationale:

1. **D-08 constraint:** Phase 15 explicitly excludes moving live agent ownership or turn lifecycle. The orchestrator's `assemble_agent` directly constructs `Agent` instances (line 146: `let mut agent = Agent::new(resolved)`) and wires providers, tools, hooks, and executors. Narrowing it to produce `AgentSpec` instead of a fully built `Agent` requires all downstream consumers of the assembled agent to switch to the `BuiltAgent` model — which is the live-agent-ownership migration planned for Phase 16/17.

2. **Dependency direction:** The workspace dependency flow is `orchestrator -> runtime`. Having the orchestrator delegate to `Runtime::build_agent(AgentSpec)` would require the orchestrator to import `AgentSpec` from `lattice-runtime`, which is structurally sound (runtime is already downstream of orchestrator). However, the current `AgentSpec` type lives in `lattice-runtime` and would need to either be extracted to a lower-level crate or made available to the orchestrator via a refactored dependency edge. This extraction is a Phase 16 concern.

3. **What Plan 03 DOES deliver for D-07:** The test fixture rename (changing `"code-agent"` to `"coding"` in test helpers and renaming test function names) prepares the orchestrator layer for the eventual structural narrowing. When Phase 16 implements the actual delegation, the orchestrator tests will already use the canonical `"coding"` preset string, so the narrowing can be validated against the correct names.

4. **Planned for Phase 16:** Full structural narrowing of `assemble_agent` — producing `AgentSpec` instead of directly constructing `Agent` — is deferred to Phase 16 where live agent ownership moves to runtime and the orchestrator becomes a pure conversion layer.

See also the threat_model below: T-15-05 explicitly accepts the remaining competing assembly path as a risk tracked for Phase 16 resolution.
