## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AgentSpec.preset → preset::apply_coding_preset | User-controlled preset selection gates which providers, tools, and security executor are wired |
| AgentSpec.cwd → validate_directory | User-supplied working directory is validated and canonicalized before use in sandbox construction |
| AgentSpec.security → DefaultToolExecutor | Security policy from caller (sandbox config, approved rules, policy authority) is applied to tool executor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-03 | Elevation of Privilege | `AgentSpec::coding_preset()` convenience method | mitigate | The method is a simple call to `.preset(AgentPreset::Coding)` and requires the caller to also supply `project_root` and `security`. Non-coding callers cannot accidentally receive coding tools because the preset switch is explicit and typed (not a string). Test `generic_agent_without_preset_does_not_expose_coding_tools` proves this. |
| T-15-04 | Tampering | `validate_directory` in preset.rs | mitigate | Canonical directory validation is preserved from code_agent.rs lines 137-155. cwd must be inside project_root. Path canonicalization prevents `..` traversal. RuntimeError::Config is returned for missing/non-directory/empty paths before any tool executor is constructed. |
| T-15-05 | Elevation of Privilege | Competing assembly path in orchestrator | accept | The orchestrator `assemble_agent` still exists as a profile-to-agent conversion path per D-07 (Phase 15 narrows but does not fully eliminate it). Plan 03 updates its test fixtures. Full elimination of the competing path is deferred to Phase 16/17 when live agent ownership moves to runtime. |
| T-15-06 | Repudiation | Task state seed application | mitigate | Task state seed is only applied when `spec.task_state_seed` is `Some`, preserving the explicit opt-in pattern from the deleted `build_code_agent`. Seed is loaded from previous session manifest metadata in the CLI layer — runtime does not guess or fabricate task state. |
