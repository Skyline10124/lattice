# Requirements: LATTICE v1.2

**Defined:** 2026-05-10
**Core Value:** Clear dependency direction and capability boundaries -- each layer owns its own business, and powerful agent abilities are opt-in capabilities rather than global assumptions.

## v1.2 Requirements

### Capability Bundles

- [x] **CAP-01**: Runtime/tool assembly can expose named tool bundles or presets instead of always exposing the full default tool set.
- [x] **CAP-02**: Capability model covers core, workspace, filesystem, editing, shell, planning, and web bundles, plus a coding-oriented `code-agent` preset.
- [x] **CAP-03**: Agent profiles can opt into bundles explicitly, and non-coding agents do not receive coding/editing tools unless selected.
- [x] **CAP-04**: Tool schema tests verify which tools are exposed for the code-agent profile versus a non-coding profile.

### Editing Foundation

- [x] **EDIT-01**: User can apply structured multi-file patches with add, update, and delete operations.
- [x] **EDIT-02**: Patch application reports precise hunk diagnostics when context is missing, duplicated, or stale.
- [x] **EDIT-03**: Patch writes are checked against sandbox write policy before any file is modified.
- [x] **EDIT-04**: Successful edits emit a changed-file manifest suitable for session/audit storage and final reporting.
- [x] **EDIT-05**: Legacy `patch` behavior migrates to the new structured `patch` tool, and `multi_patch` is intentionally retired from exposed capabilities with retirement/no-leak tests.

### Permission and Approval

- [x] **PERM-01**: Blocked shell/tool operations return actionable denial reasons that the model and user can understand.
- [x] **PERM-02**: Shell operations can request approval with a clear command purpose, risk class, and scoped prefix rule.
- [x] **PERM-03**: Approved command prefixes are scoped tightly enough to avoid broad arbitrary execution.
- [x] **PERM-04**: Runtime security profiles are usable consistently from CLI code-agent and runtime-built agents.

### Agent Task and Session State

- [x] **STATE-01**: Agent task state stores todos with pending, in_progress, and completed states outside plain tool text.
- [x] **STATE-02**: At most one todo can be in_progress, and state updates are visible to subsequent turns.
- [x] **STATE-03**: Tool failures and failed verification commands are summarized into turn/session context for recovery.
- [x] **STATE-04**: Code-agent sessions can resume with current plan, changed files, and unverified work visible.
- [x] **STATE-05**: Turn manifests include enough task/edit/tool metadata to audit what changed and what remains unverified.

### Code Agent

- [x] **CODE-01**: `lattice code` is backed by an explicit code-agent profile rather than one-off hard-coded CLI behavior.
- [x] **CODE-02**: Code agent loads hierarchical project instructions from `LATTICE.md`, `AGENTS.md`, and `CLAUDE.md` through provider/context mechanisms.
- [x] **CODE-03**: Code agent starts substantial work with workspace context and uses targeted file reads/searches instead of broad dumps.
- [x] **CODE-04**: Code agent protects unrelated dirty worktree changes and reports changed files, verification, and residual risk in final answers.
- [x] **CODE-05**: Code agent uses the new editing, planning, permission, and session capabilities as its default working loop.

### Evaluation

- [x] **EVAL-01**: Evaluation fixtures cover dirty worktree safety, project instruction obedience, targeted file reading, patch recovery, and verification honesty.
- [x] **EVAL-02**: Evaluation fixtures prove coding capabilities do not leak into non-coding profiles.
- [x] **EVAL-03**: Test commands for touched crates are documented per phase and included in verification criteria.
- [x] **EVAL-04**: Gap analysis against Codex and Claude Code is linked as research input and kept current for this milestone.

## Future Requirements

### Product Surface

- **FUT-01**: Mature TUI/REPL command palette for daily coding workflows.
- **FUT-02**: PTY command sessions with stdin continuation and polling.
- **FUT-03**: MCP client/server lifecycle and dynamic tool namespace.
- **FUT-04**: IDE/app server integration for editor-native workflows.
- **FUT-05**: Multi-agent delegation UX with worktree isolation and merge/review support.

### Session and Recovery

- **FUT-06**: Append-only event log for crash recovery.
- **FUT-07**: File snapshot artifact store for replaying edits without re-running tools.
- **FUT-08**: Remote push/pull for session and artifact objects.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Making all of Lattice a code-agent clone | Lattice remains a model-centric engine; code agent is one main profile |
| Full Claude Code/Codex UI parity | This milestone focuses on foundations and a strong CLI code agent |
| Remote/cloud task execution | Requires stable local session and permission model first |
| Full MCP ecosystem | Useful later, but local capabilities are the immediate bottleneck |
| Provider-specific prompt renderers | Prompt/channel metadata is already forward-compatible |
| Broad destructive approval rules | Approval prefixes must remain scoped and defensible |
