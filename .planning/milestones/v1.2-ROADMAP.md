## Phase Details

### Phase 10: Capability Bundles & Profile Isolation

**Goal:** Runtime/tool assembly exposes named capability bundles, and agent profiles opt into the exact capabilities they need.
**Depends on:** Phase 9
**Requirements:** CAP-01, CAP-02, CAP-03, CAP-04
**Success Criteria** (what must be TRUE):
1. Tool definitions can be grouped into named bundles or presets.
2. Code-agent preset receives workspace, filesystem, editing, shell, planning, and web bundles.
3. A non-coding profile can be assembled without coding/editing tools.
4. Tests assert exposed tool schemas per profile/bundle.
5. Profiles/runtime paths without explicit capability declarations fail fast instead of receiving hidden full-default tools.
**Plans:** 4/4 plans complete

Plans:
- [x] 10-01 — lattice-tools capability resolver and executor authorization
- [x] 10-02 — orchestrator profile capabilities and assembly isolation
- [x] 10-03 — runtime/CLI code-agent wiring and direct executor paths
- [x] 10-04 — cross-crate verification and metadata

### Phase 11: Structured Editing Engine

**Goal:** Lattice has a product-grade editing foundation comparable to Codex/Claude Code patch semantics.
**Depends on:** Phase 10
**Requirements:** EDIT-01, EDIT-02, EDIT-03, EDIT-04, EDIT-05
**Success Criteria** (what must be TRUE):
1. Multi-file patch input supports add, update, and delete operations.
2. Patch failure diagnostics identify missing, duplicated, or stale context.
3. Sandbox write checks happen before any file is modified.
4. Successful edits return a changed-file manifest for session/audit/final reporting.
5. New structured `patch` tests pass and `multi_patch` retirement/no-exposure tests pass.
**Plans:** 4/4 plans complete

### Phase 12: Permission & Approval Workflow

**Goal:** Risky commands and tool operations can be explained, denied, or approved with scoped rules instead of opaque allowlist failures.
**Depends on:** Phase 10
**Requirements:** PERM-01, PERM-02, PERM-03, PERM-04
**Success Criteria** (what must be TRUE):
1. Denied shell/tool operations return actionable reasons.
2. Approval requests include command purpose, risk class, and proposed prefix rule.
3. Prefix rules are narrow and reject broad arbitrary execution patterns.
4. RuntimeSecurity profiles apply consistently to CLI code-agent and runtime-built agents.
5. Tests cover approved, denied, and malformed approval scenarios.
**Plans:** 4/4 plans complete

**Wave 2** *(blocked on Wave 1 completion)*

### Phase 13: Agent Task & Recovery State

**Goal:** Planning and recovery information becomes first-class agent/session state rather than transient tool text.
**Depends on:** Phase 9, Phase 10, Phase 11, Phase 12
**Requirements:** STATE-01, STATE-02, STATE-03, STATE-04, STATE-05
**Success Criteria** (what must be TRUE):
1. Todo state persists pending, in_progress, and completed items.
2. The state model rejects multiple in_progress todos.
3. Tool failures and failed verification commands are summarized for the next turn.
4. Resume context includes plan, changed files, and unverified work.
5. Turn manifests include task/edit/tool metadata needed for audit.

### Phase 14: Main Code Agent & Eval Harness

**Goal:** `lattice code` becomes a strong main agent built from reusable capabilities, with behavior validated against Codex/Claude Code-inspired scenarios.
**Depends on:** Phase 10, Phase 11, Phase 12, Phase 13
**Requirements:** CODE-01, CODE-02, CODE-03, CODE-04, CODE-05, EVAL-01, EVAL-02, EVAL-03, EVAL-04
**Success Criteria** (what must be TRUE):
1. `lattice code` is assembled from an explicit code-agent profile/capability preset.
2. Hierarchical `LATTICE.md`, `AGENTS.md`, and `CLAUDE.md` instructions are loaded through provider/context mechanisms.
3. Code agent uses workspace context and targeted file reads/searches for substantial work.
4. Final answers report changed files, verification run, and residual risk.
5. Eval fixtures cover worktree safety, instruction obedience, targeted file reading, patch recovery, verification honesty, and profile isolation.
**Plans:** 7/7 plans complete
